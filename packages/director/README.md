# @openhiggsfield/director

The director layer beside the Cinema Studio MCP: judgement, not formatting. The Studio compiles structured shots into H3 prompts, enforces the two human checkpoints and keeps the ledger. This package adds what the Studio does not check or render yet:

| Area | What it adds | Tool |
|---|---|---|
| Style | 16 presets in the eleven-section STYLE.md convention, compiled to Studio fields (Look, negatives, per-shot cinematography defaults, allowed camera moves, transitions, sound defaults); user styles in `~/.openhiggsfield/my-styles` shadow the library | `list_styles`, `suggest_styles`, `get_style`, `compile_look`, `apply_style` |
| Treatment | logline, arc, three candidate structures, benchmark, hook ≤ 3 s, ending echo, signature shot, native move, sequences with pace, sound design table, silences, J/L cuts → `TREATMENT.md` for `save_script` | `validate_treatment` |
| Rhythm | deterministic lint on a shotlist: pace / size / move variety, a breath, static use, beat tiling, link and mode sanity, dialogue density, render-order switches | `lint_shotlist` |
| Music grid | cue map (tempo sections, hits as bar/beat, silences), snap cuts to the grid | `check_cue_map`, `cut_on_beats` |
| Sound | extended timeline with J-cut / L-cut, fades, iris / wipe / flash, freezes, title cards and captions, narration track, music with ducking, silences, burned subtitles, loudnorm −14 LUFS; Studio-shaped projection for `save_timeline` | `check_timeline`, `assemble_local` |
| Narration | reading-time rule, SRT, digits-on-screen / words-in-speech, edge-tts adapter | `check_subtitles`, `synthesize_narration` |
| Cost | one batch plan: R2VA first, linked shots after their anchors, one estimate against the cap | `plan_batch` |
| Docs | the director guide (judgement) and the H3 technique guide (constraints), split | `get_guide` |

## Use

```bash
pnpm install
pnpm --filter @openhiggsfield/director build      # compiles and regenerates styles/*/STYLE.md
pnpm --filter @openhiggsfield/director test
```

The repo's `.mcp.json` registers the server as `director` (stdio). With the Studio MCP connected too, the flow is:

1. `get_guide('director')`; `suggest_styles(topic)` → the user picks a style by name.
2. `compile_look(style, loras)` → `start_film({ brief, totalSeconds, look })`.
3. Write the treatment; `validate_treatment` → `save_script(markdown + dialogue)`.
4. Write sequences and shots; `apply_style(style, shotlist)` → `lint_shotlist` → `save_shotlist`. Fix errors and warnings before asking for approval.
5. `check_cue_map` / `cut_on_beats` for the music grid; `plan_batch` → one confirmation → `generate_take` in that order.
6. `auto_timeline` → extend it (J/L cuts, titles, narration, music) → `check_timeline` → `save_timeline(timeline)` for the Studio and `assemble_local` for the full version.

## Styles

`styles/<slug>/style.json` is the source; `STYLE.md` and `styles/README.md` are generated by the build. The eleven sections and the "invariants only, story is yours" discipline follow the convention of [lemo-opuscar](https://github.com/lemomo-ai/lemo-opuscar) (CC BY 4.0 for its texts); the presets here are written for the H3 pipeline and compile into Studio fields rather than code. Add a style by copying a folder and running the build; a style the schema rejects fails the build with the field named.

A user's own style goes in `~/.openhiggsfield/my-styles/<slug>/style.json` (or `$DIRECTOR_MY_STYLES`) and is listed first.
