# @kinora/director

The director layer beside the Kinora Studio MCP: judgement, not formatting. The Studio compiles structured shots into H3 prompts, enforces the two human checkpoints and keeps the ledger. This package adds what the Studio does not check or render yet:

| Area | What it adds | Tool |
|---|---|---|
| Style | 16 presets in the eleven-section STYLE.md convention, compiled to Studio fields (Look, constraints, per-shot cinematography defaults, allowed camera moves, transitions, sound defaults, shot lengths). A style of the user's own: a fork of any style with its sections sorted into safe / changes its character / cannot change, and a diff that says what each change costs. In the Studio these live in the database; the local MCP reads `~/.kinora/my-styles` | `list_styles`, `suggest_styles`, `get_style`, `compile_look`, `apply_style`; in the Studio also `fork_style`, `save_style`, `delete_style` |
| Treatment | logline, arc, three candidate structures, benchmark, hook ≤ 3 s, ending echo, signature shot, native move, sequences with pace, sound design table, silences, J/L cuts → `TREATMENT.md` for `save_script` | `validate_treatment` |
| Rhythm | deterministic lint on a shotlist: pace / size / move variety, a breath, static use, beat tiling, link and mode sanity, dialogue density, render-order switches | `lint_shotlist` |
| Craft | staging in screen terms (blocking, the 180° line, exits), what moves (dead frames), eye level at most twice, no run of one size, frame plans, handles; wording the model misreads (loose directions, negations, unison reactions, "cartoon"); the pictures AI video gets wrong (`fragile.*`, and a fragility score for the batch probe); treatment turns as problem → solution → reaction | `lint_shotlist`, `validate_treatment` |
| Music grid | cue map (tempo sections, hits as bar/beat, silences), snap cuts to the grid | `check_cue_map`, `cut_on_beats` |
| Sound | a timeline in the director's shape (transitions, J-cut / L-cut, freezes, title cards and captions, narration, music with ducking, silences, fades, a loudness target), checked and translated to what the Studio's `save_timeline` takes; the Studio's assembler renders it. The same timeline renders locally with ffmpeg from take files | `check_timeline`, `assemble_local` |
| Narration | reading-time rule, SRT, digits-on-screen / words-in-speech, edge-tts adapter | `check_subtitles`, `synthesize_narration` |
| Cost | one batch plan: R2VA first, linked shots after their anchors, one estimate against the cap | `plan_batch` |
| Docs | the director guide (judgement) and the H3 technique guide (constraints), split | `get_guide` |

## Use

```bash
pnpm install
pnpm --filter @kinora/director build      # compiles and regenerates styles/*/STYLE.md
pnpm --filter @kinora/director test
```

The repo's `.mcp.json` registers the server as `director` (stdio). With the Studio MCP connected too, the flow is:

1. `get_guide('director')`; `suggest_styles(topic)` → the user picks a style by name.
2. `compile_look(style)` → `start_film({ brief, totalSeconds, look })`. LoRAs are not in the look: once the board is designed the Studio's `assign_loras` gives each shot the ones that suit it.
3. Write the treatment; `validate_treatment` → `save_script(markdown + dialogue)`.
4. Write sequences and shots; `apply_style(style, shotlist)` → `lint_shotlist` → `save_shotlist`. Fix errors and warnings before asking for approval. Then the LoRA pass: `list_loras(projectId)` → `assign_loras`, each shot its LoRAs with why (or none).
5. `check_cue_map` / `cut_on_beats` for the music grid; `plan_batch` → one confirmation → `generate_take` in that order.
6. `auto_timeline` → finish it (transitions, J/L cuts, titles, narration, music, silences) → `check_timeline` → `save_timeline(timeline)` → `export_project` → `get_export` for what was measured on the file. `assemble_local` renders the same timeline from take files on disk.

## Styles

`styles/<slug>/style.json` is the source; `STYLE.md` and `styles/README.md` are generated by the build. The eleven sections and the "invariants only, story is yours" discipline follow the convention of [lemo-opuscar](https://github.com/lemomo-ai/lemo-opuscar) (CC BY 4.0 for its texts); the presets here are written for the H3 pipeline and compile into Studio fields rather than code. Add a style by copying a folder and running the build; a style the schema rejects fails the build with the field named.

A user's own style goes in `~/.kinora/my-styles/<slug>/style.json` (or `$DIRECTOR_MY_STYLES`) and is listed first.
