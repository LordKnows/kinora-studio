# Per-shot prompt sensitivity, verified against primary sources (state on 2026-11-13)

> **What this file is.** A verification ledger for the numbers and vendor statements that `reports/LLM agent在AI视频制作中的作用.md` takes from `per_shot_prompt_sensitivity.md`, plus what the official guides say now that they could be opened. Every item below was read in the primary source itself (arXiv HTML full text of the latest version; vendor pages; model repositories) on 2026-11-13. Evidence tags: **[M]** measured, **[V]** vendor / official guide, **[A]** anecdote. Verdicts: CONFIRMED / CORRECTED / NOT FOUND / NOT REACHABLE.
>
> **CORRECTIONS THAT CHANGE WHAT THE REPORT SAYS (read these first)**
>
> 1. **StoryEval "Wan2.2 45.9%" is the no-prompt-enhancer row, and the same paper raises it to 64.6% by changing only the prompt.** CAPE-T2V Table 1: Wan2.2, PE = None, Original DiT, StoryEval Overall 45.9; with the paper's caption-anchored enhancer and the *same original weights*, 64.6 (+18.7); Wan's own official enhancer gives only 47.5 (+1.6). The report uses 45.9% as evidence that multi-event limits hold "regardless of wording" ("有些限制换什么措辞都过不去"). The cited paper shows the opposite for this benchmark: prompt format moved event completion by 19 points on fixed weights. The "<50% for all 11 models" result is from the 2024 StoryEval paper on 2024 models and is confirmed as such.
> 2. **SeqBench 0.366 is not "multi-subject multi-action".** In Table II the 0.366 sits in the column MSSA = Multi Subject-**Single** Action. Kling 2.0's multi-subject multi-action (MSMA) scores are 0.192 / 0.258 / 0.228. The paper's own prose mislabels it ("multi-subject multi-action scenarios (MSSA_FO: 0.366)"). Also, 0.266 (SSMA_SS) must be read next to the single-action baseline: Kling 2.0 scores only 0.291 on single-subject single-action (SSSA) on this metric, so the drop from one action to several is 0.291 → 0.266 / 0.209 / 0.207, not "from near 1 to 0.27".
> 3. **RAPO 248 / 246 / 256 is the EvalCrafter "Final Sum Score" (Table 5), not an ablation**, and 80.89% / 79.75% are in RAPO's own VBench table (Table 4) as well as RAPO++'s (Table VI). The 79.75% row is the Open-Sora prompt refiner, not GPT-4; GPT-4 rewriting scores 79.69%. Values themselves are right.
> 4. **Video-T1 "+5.86" is a relative percentage printed in the table ("86.51+5.86%"); the absolute gain from the printed numbers is +4.90.** The printed percentage is inconsistent with the row's own baseline (81.61 → 86.51 is +6.00%); +5.86% matches the Pyramid-Flow (SD3) baseline 81.72 in the row above. Use "81.61 → 86.51 (+4.90 points)".
> 5. **Adaptive Low-Pass Guidance: both 33% and 36% are real, from different versions.** v1 abstract (June 2025): "average improvement of 36% in dynamic degree" on VBench-I2V. v2 (Feb 2026, the current text): "33% average improvement across models", with 36.3% for Wan 2.1 alone (appendix). Both are relative increases of the VBench Dynamic Degree score, not percentage points.
> 6. **PRIS "15%" is not VBench-2.0 total.** It is +15.19 points on the *Controllability & Creativity category average* for Wan2.1-14B (53.66 → 68.85; best-of-N alone reaches 58.51), Table 2. The baseline already uses Wan's standard prompt expansion.
> 7. **The H3 caption format is MiniMax's own, not lightx2v's.** `integrated_multimodal_description / overall_soundscape / non_diegetic_music` (and the six-section Ref2VA format) are defined in MiniMax's official prompt guides and are the output format of MiniMax's hosted enhancer, H3-Context-IR. The report and HANDOFF.md attribute the format to the lightx2v turbo LoRA's training captions; lightx2v's repo only repeats it.
> 8. **"No CFG" is a property of the official base weights, not of the turbo LoRA.** MiniMax's model card: "The released checkpoints are CFG-distilled Omni Transformer model weights." So the absence of a negative-prompt branch applies to the 20-step / 50-step base too.
> 9. **The official H3 format has no numeric time ranges inside a shot.** Timecodes appear only on cuts (`[Shot 2] At 00:03.500, the camera cuts to...`); the first shot carries no timestamp; within a shot, MiniMax's own enhancer output uses prose ("Early in the clip", "As the clip progresses into the middle seconds"). ComfyUI's H3 guide adds: "Use a single timestamp (`At 00:05.000`), not a range like `[5s-8s]`". The report's sentence "H3 接受带时间窗的节拍" has no support in the official material; it is supported only by one hosted-product anecdote (PixelDojo), where the hosted enhancer rewrites the prompt first.
> 10. **In image-to-video, MiniMax's guide says to describe the image first** ("The description should first establish the style, subjects, composition, and scene anchors in the image, then describe the next action"). This is the opposite of Runway's and Kling's advice. The report's "首帧模式下，画面归图，文字归运动" is confirmed for Runway, Kling, Sora and Seedance, and is *not* what the official H3 guide prescribes for I2VA. (For FL2VA the H3 guide does say not to repeat the two image descriptions.)
> 11. **"Negations do not work" is not vendor-universal.** Confirmed for Runway Gen-4 (exact quote below) and stated for the H3 open weights by ComfyUI's guide. But ByteDance's official Seedance 2.0 guide says "约束词十分重要" and gives "不要生成Logo" as a template, the Seedance 2.5 guide has a "负向控制" section and prescribes "人物眼睛不发光" as the fix for glowing eyes, Google's Veo 3.1 guide has a "Mastering negative prompts" section, and OpenAI's own Sora 2 example contains "Avoid signage or corporate branding."
> 12. **The Hailuo citation is split across two articles.** "2-3 rerolls for a complex trajectory match" is in the trajectory-matching article. "Use the last frame of the previous clip as the next clip's reference" is *not* in that article (it says to use the same master image for every shot); it is in a different Hailuo knowledge article. Both are dated Jul 27, 2026 (before H3's Jul 31 launch), speak of 4-6 s clips, and describe themselves as "internal studio heuristics, not a controlled lab study".
> 13. **Two gaps in the earlier notes are now filled.** (a) A teacher-vs-few-step table of VBench Semantic score exists (TMD Tables 1-2, rCM Table 2, Self Forcing Table 1); for 4-step students of Wan2.1 the gap runs from −3.3 to +2.0 points depending on method and on which prompt augmentation the teacher was scored with, and one older distillation (CausVid) is 10.3 below. (b) "Dense prompt → better dense prompt" has partial measurements: WanPE's shot-level requests still gain +13.45, and CAPE-T2V prices the residual within-schema mismatch at 0.3-1.6 points.
> 14. **Seedance reference limits, resolved from the official table:** Seedance 2.0 series 15 (9 images + 3 videos + 3 audio); Seedance 2.5 50 (30 images + 10 videos + 10 audio). The earlier notes' "9 / 12 / 15" conflict was third-party noise. H3: 9 images, 3 videos, 3 audio, at most 12 files in total.
>
> **Not reachable:** the Zhihu article behind "more than 2-3 shot changes go wrong" (HTTP 403). Its *other* claim (exact times like "0-3 秒" are unstable on Seedance 2.0) is in the official Seedance 2.0 guide verbatim.

## 1. Verification ledger for the cited papers

### Takeaway
All eleven arXiv ids resolve to the papers described, and every number the report uses exists in the source; six needed a corrected label, scale or baseline (see the block above). The two readings that change are StoryEval/Wan2.2 (the 45.9% is a no-enhancer baseline that prompt format alone lifts to 64.6%) and SeqBench (the 0.366 is single-action, and the metric's single-action baseline is itself only about 0.29).

### Inferences
- The report's structural claim survives verification but its strongest sentence does not. "Some limits no wording gets past" should be narrowed to what the tables show does not move: direction-of-motion binding (flat under every method in VQQA Table 1) and multi-subject multi-action coherence. Ordered multi-event completion and mid-clip attribute change *do* move with prompt format or prompt revision (CAPE-T2V +18.7 on StoryEval; PRIS Dynamic Attribute 48.89 → 73.33; Motion Order 43.33 → 66.67), though they stay far from solved.
- The size of the format effect depends on the enhancer more than on the model: on the same Wan2.2 weights the official enhancer is worth +1.6 StoryEval points and a caption-anchored one +18.7; on LTX-2.3 the official one is worth +24.6. "Use the model's enhancer or its trained format" is therefore not one lever of fixed size; it has to be checked per model.
- Three partial measurements now bound "dense → better dense": already-shot-level requests still gain 13.45 preference points from recasting (WanPE); revision after seeing the output adds about 10 points over best-of-N on already-expanded prompts (PRIS); and once the schema matches, the residual phrasing mismatch is worth 0.3-1.6 points and needs model fine-tuning to collect (CAPE-T2V). Together: schema and reactive revision matter, phrasing inside a matched schema is the smallest term. This supports the report's ordering with numbers it did not have.
- Every one of these is an author-reported result; WanPE's comparison against MiniMax's enhancer is by a competitor.

### Gaps
- None of the eleven papers reports seed-level variance or confidence intervals for the headline numbers, except that CAPE-T2V averages over a 3×3 seed grid and WanPE gives lower/upper preference bounds.
- WanPE does not state how many comparisons fall in each sub-table, only the "∼11K" total.
- Not re-verified because the report does not use them: VPO (2503.20491), Prompt-A-Video (2412.15156), VARI (2610.18189), the 2026 few-step papers 2609.39132 / 2607.06631 / 2606.18478 / 2603.16870, and the Seedance 2.0 report (2604.14148).

## 2. MiniMax H3 (Hailuo 3): what MiniMax's own material says

### Takeaway
MiniMax publishes the exact caption format H3-Base expects, as two prompt guides, an agent skill, and a hosted enhancer (H3-Context-IR) whose output *is* that format; it calls the enhancer "critical to the quality of the final output". For a self-hosted ComfyUI setup the enhancer does not exist, so the guides are the specification the compiler has to meet, and they differ from the project's compiled prompts in several concrete ways (header placement, FL2VA header wording, numeric beat ranges, a `Camera:` label, describing the first frame).

### Cited Findings

**Prompt structure (base modes: T2VA / I2VA / FL2VA / L2VA)**
- [V] Part one is a fixed instruction line, "the first line of the final prompt, followed by one blank line before the core fields". "**T2VA** has no image-alignment instruction and begins directly with the three core fields." I2VA "always uses": `For the target video, at 0.00 seconds into the target video, <Picture 1> (from [Shot 1]) is fully referenced.` FL2VA "always uses": `How the reference pictures align with the target video — Picture 1 (from Shot 1) aligns with the 0.00-second mark of the target video; Picture 2 (from Shot N) aligns with the S.SS-second mark of the target video.` L2VA: `How the reference pictures align with the target video — <Picture 1> (from [Shot N]) aligns with the S.SS-second mark of the target video.` "`S.SS` is the effective video duration formatted to exactly two decimal places." — [H3 base prompt guide](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_base_en.md)
- [V] Part two: `integrated_multimodal_description: [Shot 1] ...` ("visuals, actions, shots, speakers, dialogue, singing, and diegetic audio along the timeline"), `overall_soundscape:` ("1-4 English sentences ... ambient sound, physical action sounds, and non-verbal human sounds"; "Use `N/A` only when the user explicitly requests complete silence"), `non_diegetic_music:` ("1-3 English sentences ... instrumentation, speed, rhythm, and dynamic changes; do not use abstract mood words"; "`N/A` when there is no non-diegetic music"). "At the beginning of `[Shot 1]`, state the overall style and initial composition", e.g. `[Shot 1] Live-action, cinematic, a medium-wide shot frames...`. Prompts are written in English; dialogue and visible text keep their language. — [H3 base prompt guide](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_base_en.md)
- [V] Length: no word count for base modes. For reference mode: "For generation tasks, `detailed_description` is normally 350-500 English words... A single shot does not automatically justify a shorter description." "Make `detailed_description` as detailed and explicit as possible... Avoid reducing the description to a plot summary". — [H3 reference prompt guide](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_ref_en.md)

**Shots, cuts and timing**
- [V] "Do not add a timestamp to the first shot. Use sequential shot numbers for later shots, and begin each one with a strictly increasing cut time that falls within the video duration: `[Shot 2] At 00:03.500, the camera cuts to...`" Cut verbs: "`the camera cuts to`, `the shot cuts to`, `the shot transitions to`, `the shot changes to`, or `the shot switches to`"; dissolve, fade or wipe "when explicitly requested". "A cut should introduce new information about the subject, space, state, viewpoint, or time. If only the distance or a slight angle needs to change, prefer camera motion." — [H3 base prompt guide](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_base_en.md)
- [V] No syntax for timed beats inside a shot is documented. In MiniMax's own enhancer output for an 8 s single shot, time is written as prose: "throughout the entire eight-second duration", "Early in the clip", "As the clip progresses into the middle seconds", "Throughout the remainder of the clip". Recommended single-shot orders are sequences of states: I2VA "first-frame anchor → action onset → continuous development → result or reaction"; FL2VA "first-frame state → observable intermediate changes → progressively narrowing differences → last-frame state". — [reproducible FL2VA script](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/scripts/readme/reproducible-768p-fl2va-request.sh); [H3 base prompt guide](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_base_en.md)
- [V, ComfyUI's guide for the open weights] "Use a single timestamp (`At 00:05.000`), not a range like `[5s-8s]`"; "Cut times increase and stay within clip duration"; for dialogue, "Tie lines to visible events, not timecodes." — [ComfyUI MiniMax H3 prompt guide](https://docs.comfy.org/tutorials/video/minimax/minimax-h3-prompt-guide)
- [V] No statement anywhere in MiniMax's material on how many shots or beats one generation executes reliably. Official examples use 1-3 shots in 5-10 s. FL2VA "generally favors a single shot so the model can interpolate continuously from the first frame to the last frame. Use multiple shots only when they are explicitly specified." — [H3 base prompt guide](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_base_en.md)

**Camera vocabulary**
- [V] "Camera Motion: Motion Type + Amplitude + Speed." Types: `Zoom In / Zoom Out`, `Push In / Pull Out`, `Pan Left / Pan Right`, `Truck Left / Truck Right`, `Tilt Up / Tilt Down`, `Pedestal Up / Pedestal Down`, `Arc Shot`, `Tracking Shot`, `Static Shot`, `Shake Slightly / Shake Strongly`, `POV`, `Roll Clockwise / Roll Counterclockwise`. Amplitude: `with small amplitude` / `with large amplitude`. Speed: `at slow speed` / `at fast speed`. "Add amplitude and speed only when they are meaningful; medium amplitude and normal speed are usually omitted." "Camera motion should be written as a natural English action within the shot, rather than stacked as separate labels at the end of a sentence", e.g. "The camera pushes in with small amplitude at slow speed toward the folded letter in her hands." — [H3 base prompt guide](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_base_en.md)

**Dialogue, audio, on-screen text**
- [V] Speakers get stable IDs "`(S1)` and `(S2)`", compound `(S1,S2)` for speaking together; "characters who never vocalize receive no speaker ID". "Inside `<d>`, include only the language tag and the actual user-provided spoken content. Preserve every original word and punctuation mark verbatim". Example: `The young woman with a quiet, breathy voice (S1) says: <d>[English] I get off at the next station.</d>`. Voiceover: "use the exact phrase `says in an off-screen voiceover`" and then state "that the corresponding on-screen character's lips remain closed". A line crossing a cut: "`<scenetrans>` at the connecting points in both parts"; speech cut by the clip end: "`<cutoff>`". — [H3 base prompt guide](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_base_en.md)
- [V] "Dialogue, singing, and diegetic music already belong in the multimodal description and should not be repeated" in `overall_soundscape`. On-screen text: "Place any banner, sign, label, subtitle, or neon text that is actually visible on screen in English double quotation marks. Preserve the original text and punctuation verbatim", e.g. `A red neon sign reading "营业中" glows above the doorway.` — [H3 base prompt guide](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_base_en.md)
- [V, ComfyUI] "If unwanted speech appears, fill both fields explicitly"; "Ellipses often hurt intelligibility"; "Multi-speaker + audio refs: Wrong-speaker assignment can happen." — [ComfyUI MiniMax H3 prompt guide](https://docs.comfy.org/tutorials/video/minimax/minimax-h3-prompt-guide)

**How the text differs by mode**
- [V] I2VA: "`<Picture 1>` is the actual first frame of the video at 0.00 seconds and belongs to `[Shot 1]`. The description should first establish the style, subjects, composition, and scene anchors in the image, then describe the next action. Character identity, clothing, colors, key objects, and spatial relationships should remain consistent." Worked example: "the young woman shown in <Picture 1> remains beside the rain-covered train window, preserving her appearance, clothing, seat position, and the carriage layout." MiniMax's own enhancer output for a first-frame request spends its first 247 words (of 553 in the description field, 726 in the whole prompt) describing what is in the image before the first change over time ("Early in the clip, ..."). — [H3 base prompt guide](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_base_en.md); [reproducible FL2VA script](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/scripts/readme/reproducible-768p-fl2va-request.sh)
- [V] FL2VA: "The body should not repeat two static image descriptions; instead, it should supply the motion path that connects them." "Focus on how the subject moves, how poses change, how objects are manipulated, how the composition evolves, and how the scene or lighting transitions." "The last frame must be reached by the final `[Shot N]` at the end of the video." L2VA: "Infer a plausible earlier state ... then describe how the characters, objects, camera, and scene gradually approach the reference image." — [H3 base prompt guide](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_base_en.md)
- [V] Reference mode: six sections in order, `subject_definitions`, `summary`, `retention_analysis`, `detailed_description`, `overall_soundscape`, `non_diegetic_music`. Labels `<Subject N>` (reusable visible content), `<Picture N>` (an image used as "a shot's first frame, keyframe, last frame, edited keyframe, or composition anchor"), `<Video N>`, `<Audio N>`. "If an image is used only to define a character, scene, costume, or style, do not create a standalone picture entry. Instead, cite the image source inside the corresponding `<Subject N>` definition", e.g. `<Subject 1> is the young woman in <Picture 1>, with long dark hair, a blue cardigan, and a thin silver necklace.` `summary` opens with a task-type prefix such as `[reference generation]` or `[video editing + reference generation + audio reuse]`. Retention markers for visible content: `fully_preserved`, `partially_preserved`, `attribute_transfer`, `weak_reference`; for audio: `fully_copy`, `partially_copy`, `reference`, `weak_reference`. In reference mode the style opening goes "in one or two English sentences before `[Shot 1]`", not after it. "At the first clear appearance of an important `<Subject N>`, describe its referenced characteristics, position in the frame, and current action". — [H3 reference prompt guide](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_ref_en.md)
- [V] The agent skill (`h3-prompt-writing`) bundles the same two guides byte-for-byte as `references/base-en.txt` and `references/ref-en.txt` and adds: "Always match the total duration of the description to the requested video length (4-15 seconds)"; "Prefer concrete visual and audio details over abstract words like 'cinematic' or 'beautiful'"; "When using keyframes (I2VA / FL2VA / L2VA), clearly state how the first and/or last frame connects to the timeline"; "Avoid plot summaries, unresolved reference labels, and timing that does not match the requested duration." — [MiniMax-AI/MiniMax-H3 SKILL.md](https://github.com/MiniMax-AI/MiniMax-H3/blob/main/skills/h3-prompt-writing/SKILL.md)

### Inferences
- Which official advice applies where. **Weights (the user's setup):** the caption format in both guides, the camera vocabulary, the speaker / `<d>` syntax, the instruction lines, 4-15 s and the 768-pixel short side, "no negatives", and the turbo caveats. **Hosted product only:** H3-Context-IR, `prompt_expansion_mode`, 2K regeneration, the 7,000-character limit, the Highspeed / Lite / Max variants, and every practitioner test found (they all ran with the expander on, so they test the expander plus the model, not the model's response to a raw prompt).
- The report's point that the compiler "does the enhancer's job" is now supported by MiniMax's own wording ("build your own context-processing system"), and the stakes are stated by the vendor: the enhancer is "critical to the quality of the final output". The differences listed above are therefore the first thing to test, before any wording rule: they are deviations from the one format the vendor says the base model reads. Whether they cost anything is unmeasured; nobody has published a with/without comparison on H3-Base, and WanPE's +5.17 is the only third-party number showing that prompt content matters on H3-Base at all.
- The official I2VA instruction to restate the first frame's subjects and composition reads as a consequence of how H3 was trained (captions describe the whole target video and its relation to the context), not as general I2V advice. For H3, "spend the prompt on motion" is right for FL2VA and is contradicted for I2VA by the model's own guide.
- Every party that ships a few-step H3 (lightx2v, FastVideo) and both integrators (MiniMax, ComfyUI) describe the cost as motion, audio and reference fidelity. None mentions text following. That is absence of a statement, not evidence of parity.
- The timing evidence on H3 is thin and one-directional: the official format times cuts only, the vendor's enhancer writes within-shot time as prose, and one anecdote shows a timed line landing 2.3 s late. The project's one internal take (a slide finished in 0.5 s instead of 2.5 s) fits. Numeric beat windows are an untested extension of the trained format.

## 3. Seedance 1.5 Pro, 2.0 and 2.5: what the official Volcengine / BytePlus guides say

### Takeaway
The timestamp claim is confirmed verbatim in the official Seedance 2.5 prompt guide, and the 2.0 guide independently says exact times are unstable. ## 4. Runway, Kling, Veo 3.1 and Sora 2: the two quoted statements, and where guides disagree

### Takeaway
Both statements the report quotes are confirmed word for word: in image-to-video the image carries subject, composition, lighting and style and the text should describe motion (Runway, Kling, Sora); and Runway Gen-4 interprets what should happen, not what should be avoided. The guides disagree with each other on negatives, on timestamps, on restating the image, and on prompt length.

### Cited Findings

**Confirmed statements**
- [V] Runway, Gen-4 Video Prompting Guide (updated 2026-07-30): "Use positive phrasing only. Gen-4 is designed to interpret prompts that describe what should happen in your video, not what should be avoided. Negative phrasing is not supported and may produce unpredictable or even opposite results. ❌ No camera movement. The camera doesn't move. NO MOVEMENT ✅ Locked camera. The camera remains still." — [Runway Gen-4 Video Prompting Guide](https://help.runwayml.com/hc/en-us/articles/39789879462419-Gen-4-Video-Prompting-Guide)
- [V] Same guide: "Focus on describing the motion, rather than the input image. Both text and image inputs are considered part of your prompt. Reiterating elements that exist within the image in high detail can lead to reduced motion or unexpected results in the output." "The input image establishes the visual starting point ... by conveying key visual information about subjects, composition, colors, lighting, and style— allowing you to focus on describing the desired motion." "The Gen-4 model thrives on prompt simplicity ... beginning your session with a simple prompt, and iterating by adding more details". — [Runway Gen-4 Video Prompting Guide](https://help.runwayml.com/hc/en-us/articles/39789879462419-Gen-4-Video-Prompting-Guide)
- [V] Runway, Image to Video Prompting Guide (for Gen-4.5; updated 2026-04-20): "your image defines composition, subject matter, lighting, and style ... Your prompt's role is to describe what should happen — the motion, camera work, and temporal progression"; "Effective image to video prompts focus almost exclusively on motion. Rather than describing elements present in the image, use your prompt to describe the motion of the scene." Exceptions listed: "Introducing an element not present in the image; Dramatic changes from the starting image; Specifying transformation details; Specifying interactions between two (or more) elements". "Creating with Gen-4 Video" (updated 2026-10-28): "your text prompt should be almost entirely focused on describing the desired motion." — [Runway I2V Prompting Guide](https://help.runwayml.com/hc/en-us/articles/48324313115155-Image-to-Video-Prompting-Guide); [Creating with Gen-4 Video](https://help.runwayml.com/hc/en-us/articles/37327109429011-Creating-with-Gen-4-Video)
- [V] Kling (Kling AI Team, Jul 10, 2026; a tutorial page on kling.ai, not the API docs): "Should I describe the whole scene again in the motion prompt? No — the source image already establishes the subject, setting, and composition. Repeating that in the prompt wastes the one slot that's actually different for video: the motion itself." - [V] Sora 2 (OpenAI cookbook, "Updated - March 2026", page marked archived): "The model uses the image as an anchor for the first frame, while your text prompt defines what happens next." - [V] Veo 3.1 (Google Cloud blog, October 16, 2025): formula "[Cinematography] + [Subject] + [Action] + [Context] + [Style & Ambiance]"; "The [Cinematography] element of your prompt is the most powerful tool for conveying tone and emotion." - [V] Restating the image. Runway, Kling, Sora, Seedance 2.5 ("减少画面复述"): do not. MiniMax H3 I2VA: do ("first establish the style, subjects, composition, and scene anchors in the image"). — [Runway](https://help.runwayml.com/hc/en-us/articles/39789879462419-Gen-4-Video-Prompting-Guide); [H3 base prompt guide](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_base_en.md)
- [V] Length and density. Runway: start simple, "thrives on prompt simplicity". Kling: "length isn't the goal". Seedance 2.0: "描述尽量简洁". MiniMax H3: "as detailed and explicit as possible", 350-500 words for one field. Sora 2: both are valid, "detailed prompts give you control and consistency, while lighter prompts open space for creative outcomes". — [Runway](https://help.runwayml.com/hc/en-us/articles/39789879462419-Gen-4-Video-Prompting-Guide); [H3 reference prompt guide](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_ref_en.md); [OpenAI](https://developers.openai.com/cookbook/examples/sora/sora2_prompting_guide)
- [V] Shots per generation. Runway Gen-4: one scene. Sora 2: several are "also valid" if each block has "one camera setup, one subject action, and one lighting recipe". Veo 3.1 and Seedance: multi-shot in one prompt is a documented workflow. H3: native multi-shot, single shot preferred for first-and-last-frame. — sources as above
- [V] Dialogue syntax differs for every model: Veo and Seedance 1.5 quotation marks; Seedance 2.0 braces "{}"; Sora 2 a separate "Dialogue:" block; H3 `(S1)` plus `<d>[Language] ...</d>`. — sources as above

### Inferences
- What is common to all of them reduces to three rules: write visible, physical actions rather than feelings; one camera job and one main action per shot; give references explicit roles. Everything else in the report's "six vendors agree" (negatives, timing, image restatement, length) is model-specific. The report's sentence that the six guides "在这一点上一致" is right for "ask for less per generation" and should not be extended to negation.
- The disagreements are an argument for the report's conclusion that prompt form belongs in a per-model compiler: four separate writing rules flip between models, two of them between adjacent versions of the same model family.
- Two vendors give, in their own words, the claim the project marks as unmeasured: Sora 2 says shorter clips follow instructions more reliably and suggests 4 + 4 over 8. That is a vendor statement about another model, not a measurement, and not about H3.

### Gaps
- Veo's API-level `negativePrompt` documentation and the Gemini-API Veo prompt guide were not read (the Gemini API page now states "The Veo 3.1 Preview in the Gemini API has been shut down" and documents Gemini Omni Flash instead).
- Kling's developer documentation (multi-shot toggle, negative-prompt field) was not re-opened; the Kling page verified here is a marketing tutorial.

## 5. Is there a measurement separating first frame, text and seed in I2V, or teacher versus few-step prompt adherence?

### Takeaway
Teacher-versus-student tables of prompt-following exist for Wan2.1. The better 4-step, no-CFG students land within about ±3 VBench-Semantic points of the 100-evaluation teacher, the sign depending on the distillation method and on the prompt augmentation used to score the teacher; one earlier distillation of the same base loses 10 points. Nothing was found that apportions outcome variance between first frame, text and seed in image-to-video; the nearest results are three single-factor measurements.

### Inferences
- The earlier notes' mechanism argument ("with CFG at 1, text conditioning is not amplified, so prompt following is weaker") is not borne out where it has been measured: on Wan2.1, 4-step no-CFG students are within −3.3 to +2.0 Semantic points of the CFG teacher, and the spread between distillation methods (11.5 points between CausVid and Self Forcing on one base) is larger than the teacher-student gap of the good ones. The practical reading for H3: whether the lightx2v 8-step LoRA follows prompts as well as the base is a property of that particular LoRA and can only be settled by the in-house A/B the report already lists. For H3 specifically, "no CFG" is not even a difference between turbo and base, since the base is CFG-distilled.
- These comparisons use VBench Semantic, which scores object, scene, colour, spatial relation and overall consistency on short single-shot prompts. It does not test timed beats, cuts, camera amplitude or dialogue, which are what the project's prompts ask for. A student can match on VBench Semantic and still be weaker on those; the vendors' "softer motion/audio" remarks point that way.
- For I2V the available numbers say: text can move how much motion there is (about +7 Dynamic Degree points from rewording), and on image-fidelity metrics neither text nor seed moves much because the image fixes them. That fits the report's "the first frame sets the ceiling for look; motion is still drawn", with the caveat that it is assembled from three unrelated experiments on Wan and CogVideoX.

### Gaps
- No study found, for any model, that varies first frame, text and seed in one design and reports their shares. Two targeted searches on 2026-11-13 returned only the papers above.
- No teacher-versus-student comparison on human-rated prompt following, on multi-shot or timed prompts, on I2V with reference images, or on any audio-video model; nothing for H3 turbo, FastH3 or Seedance's fast variants.
- The Wan-based comparisons mix a second variable (CFG and a negative prompt on the teacher only), so they do not isolate step count from guidance.
